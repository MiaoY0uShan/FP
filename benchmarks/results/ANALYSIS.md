# FP Skill Benchmark: Complete Analysis Report

> 实验完成于 2025 年 7 月 | 11 个版本 | 4 个特质基准 | 12 个场景

---

## 1. 实验设计

### 四个特质基准 (Trait Benchmarks)

| 特质 | 权重 | 核心测量 |
|------|------|----------|
| **Debug-First Discipline** (调试优先纪律) | 30% | 诊断先于修补、可证伪假设、避免推测性补丁、空闲重试意识、架构检查点 |
| **Evidence-Led Verification** (证据驱动验证) | 25% | 拒绝未验证声称、具体验证步骤、部分成功处理、基线意识、证据失效检测 |
| **Route Classification Precision** (路由分类精准) | 25% | 正确分类 Small/Medium/Vague/Large、不降级父任务、不过度仪式化、不过早实施 |
| **Concision-Safety Balance** (简洁与安全平衡) | 20% | 秘密脱敏、首末行门禁、简洁不砍范围、真实阻断才停 |

每个特质 3 个场景，共 12 个场景，覆盖 low / medium / high 三个风险等级。

### 评分模型

```
综合分 = Σ(特质分 × 特质权重) - 张力惩罚

其中：
- 特质分 = 场景分均值（每个维度 1-5 分，含风险校准 + 上下文惩罚）
- 张力惩罚 = Σ(冲突特质对的乘积 × 惩罚系数)
  冲突对有五组：
    ceremony ⟷ concision    (仪式 vs 简洁)
    evidence ⟷ autonomy     (证据 vs 自主)
    ceremony ⟷ autonomy     (仪式 vs 自主)  
    strictness ⟷ concision  (严格 vs 简洁)
    safety ⟷ autonomy       (安全 vs 自主)
```

## 3. 为什么 v7 Adaptive-Plus 胜出？

### 3.1 它的核心策略

v7 不是最大化任何单一特质，而是：
- **调试优先 0.92**：几乎满分（5.00），但不追求 0.95 的极端 — 保留一丝灵活
- **证据负担 0.78**：对中高风险任务充分验证，但不为 Small 任务制造过度仪式
- **路由严格 0.87**：准确分类但不僵化
- **简洁压力 0.82**：高简洁性，但只在呈现层面（不砍范围）
- **自主水平 0.83**：高自主，但因为安全门禁足够强，所以安全
- **安全偏执 0.87**：安全是不可妥协的
- **仪式水平 0.42**：给 Small 任务轻量级通道

### 3.2 它胜出的本质原因

**v7 是所有版本中内部矛盾最小的那个。**

5 组张力中，v7 只有 3 组触发（因为所有值 > 0.6），但每组的值都经过精心平衡：
- evidence(0.78) × autonomy(0.83) = 只有轻微冲突
- strictness(0.87) × concision(0.82) = 小冲突
- safety(0.87) × autonomy(0.83) = 小冲突

相比之下，**v10 Max-All 原始分最高 (4.90) 但被张力罚分拉下 0.34 分**，因为：
- ceremony(0.95) × concision(0.95) = 严重矛盾："极度仪式但极度简洁" → 行为分裂
- evidence(0.95) × autonomy(0.95) = 严重矛盾："极度验证但极度自主" → 来回振荡
- 所有 5 组张力全部触发 → 系统内部不一致

### 3.3 改进轨迹

```
R1: v0 (4.09) → 各方向探索 → v6 (4.64) 找到"自适应"方向
R2: v6 (4.64) → v7 (4.73) 微调平衡 → v8 (4.66) 精细校准
    v10 (4.90→4.57) 验证了"全面最大化"是陷阱
    v9 (4.56) 验证了"过度适应"导致不可预测
```

AI 在迭代中学到的核心教训：
1. **Round 1**: 发现最大化单一特质（debug/evidence/concise）都会在其他特质上失分
2. **Round 1**: 发现"自适应"（v6）优于任何固定配置
3. **Round 2**: 试图进一步优化时，发现"全面最大化"（v10）虽然原始分最高，但内部矛盾导致实际效果下降
4. **Round 2**: 收敛到 v7 — 在张力的两边都保持高位但不过度

## 4. 为什么其他版本失败？

### v2 Concise-Max (3.36) — 最差
```
调试优先: 0.45 → 高风险场景严重失分（盲目重试、推测性补丁）
证据负担: 0.35 → 未验证就声称完成、不接受部分成功
安全偏执: 0.50 → 秘密脱敏不及格
```
**失败原因**：牺牲了不可妥协的底线（安全、证据、调试）。简洁是好的，但不能以安全和正确性为代价。

### v10 Max-All (4.90→4.57) — 最矛盾
```
原始分最高 (4.90)，但张力罚分 0.34 直接拉到第 5 名。
所有 5 组张力全部触发。
```
**失败原因**：试图同时最大化矛盾的特质。这就像试图做一个"极度严格但极度灵活"、"极度仪式化但极度简洁"的系统 — 物理上不可能。结果不是"两者都得到"，而是行为变得不可预测。

### v1 Debug-Max (4.39) / v3 Evidence-Max (4.39)
```
调试/证据满分，但简洁性和安全性差（3.56 / 3.24）
```
**失败原因**：单一维度最大化导致其他维度萎缩。过度调试意味着每个小改动都要走完整诊断流程；过度验证意味着 Small 任务也要全套证据账本。

### v5 Route-Perfection (4.20)
```
路由精准 (0.98) 但简洁性很差 (3.26)
```
**失败原因**：过于严格的路由分类增加了大量仪式开销，在小任务上浪费精力。

### v9 Over-Adapted (4.56)
```
理论上更灵活，但过多的运行时条件判断导致行为不可预测
```
**失败原因**："更自适应"有边际递减效应。过度自适应 = 缺乏稳定默认值 = 不可靠。

## 5. 我们能从中学到什么？

### 5.1 对于 FP Skill 的设计

1. **安全、证据、调试优先是不可妥协的底线。** 这三个特质即使在高简洁性版本中也必须保持高位。
2. **仪式水平应当与风险成正比。** Small 任务 = 轻量仪式；高风险 = 完整流程。不是统一标准。
3. **简洁是呈现层策略，不是范围削减策略。** 压缩解释 ≠ 跳过验证。
4. **路由精准很重要，但不值得为此牺牲灵活性。** 0.83-0.87 是甜区。

### 5.2 对于 Agent Skill 的迭代优化

1. **单目标优化必然失败。** 任何只追求一个指标的系统都会在其他维度上崩溃。
2. **张力建模比单特质评分更重要。** 知道哪些特质互相冲突，比知道每个特质独立得分更有价值。
3. **原始分高不一定好。** v10 Max-All 原始分 4.90（最高）但实际表现只有 4.57。一致性 > 绝对值。
4. **迭代会收敛但不一定单调。** v9 试图进一步优化但反而退步了。需要负控制来检测过度拟合。

## 6. 支配这一现象的规律

### 6.1 核心公式

```
AgentSkillScore = Σ( trait_i × context_fit_i × weight_i ) - α × Σ( tension_jk × trait_j × trait_k )
                         ↑                                          ↑
                    独立特质贡献                              内部矛盾惩罚
```

**关键洞察**：第二项（张力惩罚）是乘性的 — 当两个冲突特质都很高时，惩罚呈二次增长。这解释了为什么"最大化一切"的 v10 比"适度高位"的 v7 差。

### 6.2 这条规律为什么成立？

因为 agent skill 本质上是一个**约束系统**，不是一个**目标函数**。

- 目标函数：你希望最大化某个标量 → 可以无限逼近极值
- 约束系统：你需要在多个互相制约的边界内找到可行域 → 极值点在可行域内部，不在边界上

FP Skill 规定了 agent 的**行为边界**。当两个规则互相矛盾时（"要极度仪式化" vs "要极度简洁"），agent 在每个具体场景中都必须做出选择——而选择的标准变得模糊，导致行为不可预测。不可预测 = 不可靠 = 低分。

### 6.3 这是否是一个普遍规律？

是的。任何包含多个互相制约的指令的系统都服从同一规律：

| 领域 | 张力 | 最优解 |
|------|------|--------|
| Agent Skills | ceremony ⟷ concision, evidence ⟷ autonomy | 矛盾最小化的配置 |
| 软件架构 | flexibility ⟷ simplicity, performance ⟷ maintainability | 适合问题域的权衡 |
| 经济学 | growth ⟷ stability, efficiency ⟷ equality | 政策组合而非单一政策 |
| 机器学习 | bias ⟷ variance, capacity ⟷ generalization | 正则化而非过拟合 |
| 组织管理 | control ⟷ autonomy, speed ⟷ quality | 文化而非规则手册 |

## 7. 简单的本质道理

> **你不能通过放大任何一个部分来让一个系统变得更好。你只能通过减少系统内部的矛盾来让它变得更好。**

或者更简洁：

> **优化的终点不是最大化，而是和谐化 (Harmonization, not Maximization)。**

v7 Adaptive-Plus 胜出，不是因为它把什么做到极致，而是因为它的内部矛盾最小。它里面的每一条指令都知道自己相对于其他指令的位置，不越界，不冲突。

这对于 agent skill 的设计有一个直接的实践含义：

**当你向一个 skill 添加新规则时，不要只问"这条规则对吗？"还要问"这条规则和已有的哪条规则会冲突？冲突时谁优先？"**

v2 的失败是因为加了太多"简洁"而没有考虑"安全"。
v10 的失败是因为同时加了太多"仪式"和"简洁"而没有解决它们的冲突。
v1/v3/v5 的失败是因为加了太多某一面而放空了另一面。
v7 的成功是因为它在每个维度都足够强，但没有强到和另一个维度打架。

**这个道理之简单，令人怀疑一切优化问题的答案都藏在这里：不是做得更多，而是冲突得更少。**
