## 关键发现

### 1. v6 为什么赢？

v6 赢了 3 个特质，在任何特质上都不是最差。它是最 **平衡** 的版本：
- debug 碾压对手 (3.22 vs 平均 2.71)
- continue 碾压对手 (2.33 vs 平均 1.89)  
- route 满分 (3.67，并列第一)
- 在 concision 上保持竞争力 (4.33)

**v6 的核心策略是自适应 (adaptive)**：高风险时高仪式，低风险时轻量化。这让它在需要判断力的困难场景（跨会话续接、线上系统操作）中比 v7 的"稍高仪式"策略更灵活。

### 2. v7 为什么掉到第三？

v7 是模拟的冠军 (4.73)，但真实 eval 中掉到第三 (2.93)。原因：
- v7 在 **原 4 个特质上确实最好**（concision 4.56, route 3.67, evidence 2.11）
- 但在 **新 4 个困难特质上大幅落后**（continue 1.56 vs v6 的 2.33, debug 2.67 vs v6 的 3.22）
- v7 的更高仪式水平 (0.42 vs v6 的 0.40) 在需要灵活判断的场景中变成了负担
- **v7 对模拟过拟合了** — 它在模拟的评分维度上优化得最好，但真实模型的行为更复杂

### 3. v2 为什么还是最差？

v2 Concise-Max 在所有 8 个特质中赢了 **零个**。它：
- 有 2 个 blocker（最多）
- 简洁性甚至不如 v7 (4.33 vs 4.56)
- 在安全关键场景（线上系统、多智能体）上尤其差
- 验证了模拟的核心结论：牺牲安全/证据追求简洁是失败的策略

### 4. 模拟 vs 真实的差距

| 现象 | 模拟 | 真实 |

| 绝对分数范围 | 3.36–4.73 | 2.61–2.94 |

**版本间差距比模拟小得多** (0.32 vs 1.37)，说明：
1. 单轮 API 调用中，system prompt 的行为修饰效果有限
2. FP skill 的真正价值体现在多轮 session 中，而非单次调用
3. 基础模型 (gpt-5.3-codex-spark) 有强烈的默认行为，不完全被 skill 覆盖

## 方法论反思

### 什么有效
- **盲评机制**有效 — 评估者不知道版本标签
- **多特质设计**有效 — 不同版本在不同特质上各有优势
- **负控制 (v2)** 有效 — 验证了最差版本确实最差
- **新困难基准**有效 — 暴露了过度优化的风险

### 什么需要改进
- **单轮 API 调用的局限**：FP skill 是为多轮 agent session 设计的，单轮调用无法充分体现其效果
- **评估者校准**：gpt-5.6-sol 非常严苛，所有分数偏低。可能需要更详细的评分标准或校准示例
- **基础模型选择**：gpt-5.3-codex-spark 的默认"helpful assistant"行为可能掩盖了 skill 差异
- **统计显著性**：每个 (版本, 场景) 只有 1 次运行，需要多次试验来确认差异的可靠性

### 下一步
1. 增加 trials（每个场景跑 3 次取平均）
2. 尝试更强的运行模型 (gpt-5.6-sol) 看技能差异是否更明显
3. 将 FP skill 注入到真正的多轮 agent session 中测试
4. 用多轮对话而非单轮 prompt 来测试跨会话续接等场景

## 结论

**真实盲评验证了核心理论**：自适应平衡策略 (v6) 优于单一最大化策略 (v2, v7)。但效应量比模拟预测的小得多 (0.32 vs 1.37)，且排名有所不同 (v6 > v0 > v7 > v2 vs v7 > v6 > v0 > v2)。

根本原因：agent skill 的行为修饰效果在单轮 API 调用中有限。但方向性结论 (平衡 > 最大化, 简洁不能牺牲安全) 在真实评估中仍然成立。
